# AI Memory - Vehicle Counting Application

## Project Overview
PyQt5-based real-time vehicle and person counting application using YOLO detection models and tracking algorithms (SORT/DeepSORT).

## Tech Stack
- **UI Framework**: PyQt5
- **Detection Models**: YOLOv3, YOLOv8n, YOLOv11n/s, YOLOv26n, Custom trained models (Train1, Train2)
- **Model Formats**: PyTorch (.pt), ONNX (.onnx) for 2-3x speedup
- **Tracking Algorithms**: 
  - Simple Tracker (IOU-based, fastest)
  - SORT (Kalman Filter + Hungarian Algorithm, fast)
  - DeepSORT (appearance features + motion, most stable)
- **Video Sources**: Local files, RTSP streams, YouTube, webcam
- **Processing Modes**: Standard, Threaded, Optimized, Ultra

## Key Features
1. **Dual-model ensemble**: Separate person and vehicle detection
2. **Person classification**: Pedestrian vs Rider/Driver based on proximity to vehicles
3. **ROI (Region of Interest)**: Polygon-based filtering
4. **Performance optimization**: Frame skip, resize scale, adaptive FPS
5. **Visual modes**: Point label vs bounding box display
6. **Trail visualization**: Object movement tracking
7. **Real-time statistics**: Object counting by class

## Current Architecture
- `pyqt_app.py`: Main UI and application logic
- `model_loader.py`: Model loading with ONNX/PyTorch support
- `video_processor.py`: Core detection and tracking pipeline
- `sort_tracker.py`: SORT tracking implementation
- `simple_tracker.py`: Lightweight IOU tracker
- `person_classifier.py`: Pedestrian/Rider classification
- `roi_manager.py`: ROI polygon management

## Known Constraints
- RTSP streams have latency issues (buffering, lag)
- DeepSORT is slow on CPU
- Memory accumulation in long sessions (trails, tracker history)
- Ghost tracks appear during network lag
- Frame pacing issues cause stuttering

## Bug Fix Session (2026-03-26 - FPS Display Fix)
### Problem
- User reported FPS always showing same value (30.3) or stuck at 0
- FPS counter was incrementing even when no new frames were available
- FPS UI was being updated twice in same render loop causing confusion

### Root Cause Analysis
1. `render_fps_counter` was incremented at start of `_render_latest_frame()` before checking if new frame exists
2. When `version <= pending_frame_version` or `latest_frame is None`, counter still increased but no actual render happened
3. `_update_fps_summary()` was called twice: once in process FPS block (line 3906) and once in render FPS block (line 3984)
4. This caused FPS to be calculated incorrectly and display stale/wrong values

### Solution Implemented
1. Moved `render_fps_counter += 1` INSIDE the `if version > pending_frame_version` block
2. Now counter only increments when there's actually a new frame to render
3. Removed duplicate `_update_fps_summary()` call from process FPS block
4. FPS UI now updates only once per cycle with accurate render FPS

### Impact
- FPS display now accurately reflects actual frame rendering rate
- No more stuck FPS values when video is paused or no new frames
- Cleaner separation between process FPS (detection speed) and render FPS (UI display speed)

### Tradeoffs
- None - this is a pure bug fix with no negative impacts

### Remaining Tech Debt
- Consider adding separate display for Process FPS vs Render FPS for advanced debugging
- Add FPS unit tests to catch similar counting bugs in future

### Camera Admin Dashboard UX Fix (2026-03-26)
**Skill Activated**: ui-ux-pro-max

**Problems Identified**:
- Grid layout không khớp khi khởi động ứng dụng
- Combo box hiển thị "4" nhưng thực tế đang dùng "5" columns
- Preview tiles không load cho đến khi user chọn lại grid columns
- Viewport width chưa sẵn sàng khi `_apply_admin_source_grid_columns` chạy lần đầu

**Root Cause**:
- `_apply_admin_source_grid_columns` được gọi trước khi widget visible và rendered
- Viewport width trả về giá trị không chính xác (quá nhỏ)
- Grid calculation dựa trên viewport width sai → layout không đúng
- `refresh_admin_source_cards` không được trigger sau khi layout đúng

**Solutions Implemented**:

1. **Delayed Grid Application**:
   - Thêm `QTimer.singleShot(50ms)` trong `show_admin_dashboard()`
   - Đảm bảo widget đã visible và rendered trước khi apply grid
   - Tự động trigger `refresh_cards=True` để load preview

2. **Viewport Ready Detection**:
   - Check `viewport.isVisible()` trước khi tính toán
   - Nếu chưa ready, schedule retry sau 100ms
   - Fallback to widget width nếu viewport width < 400px

3. **Improved Width Calculation**:
   ```python
   if list_width < 400:
       list_width = max(800, self.admin_source_list.width() - 20)
   ```
   - Đảm bảo minimum width hợp lý cho calculation
   - Tránh grid quá chật khi viewport chưa expand

**UX Improvements**:
- ✅ Grid layout đúng ngay khi mở dashboard
- ✅ Preview tiles tự động load
- ✅ Không cần user phải chọn lại grid columns
- ✅ Smooth transition khi mở dashboard
- ✅ Consistent layout across app restarts

**Performance Impact**:
- Minimal - chỉ thêm 50-100ms delay
- Tránh multiple redundant calculations
- Preview loading vẫn async và không block UI

**Technical Details**:
- Modified: `show_admin_dashboard()` - added QTimer delay
- Modified: `_apply_admin_source_grid_columns()` - added viewport ready check
- No breaking changes to existing functionality
