# AI Memory - Vehicle Counting Application

## Project Overview
PyQt5-based real-time vehicle and person counting application using YOLO detection models and tracking algorithms (SORT/DeepSORT).

## Tech Stack
- **UI Framework**: PyQt5
- **Detection Models**: YOLOv3, YOLOv8n, YOLOv11n/s, YOLOv26n, Custom trained models (Train1, Train2)
- **Model Formats**: PyTorch (.pt), ONNX (.onnx) for 2-3x speedup
- **Tracking Algorithms**: 
  - Simple Tracker (IOU-based, fastest)
  - SORT (Kalman Filter + Hungarian Algorithm, fast)
  - DeepSORT (appearance features + motion, most stable)
- **Video Sources**: Local files, RTSP streams, YouTube, webcam
- **Processing Modes**: Standard, Threaded, Optimized, Ultra

## Key Features
1. **Dual-model ensemble**: Separate person and vehicle detection
2. **Person classification**: Pedestrian vs Rider/Driver based on proximity to vehicles
3. **ROI (Region of Interest)**: Polygon-based filtering
4. **Performance optimization**: Frame skip, resize scale, adaptive FPS
5. **Visual modes**: Point label vs bounding box display
6. **Trail visualization**: Object movement tracking
7. **Real-time statistics**: Object counting by class

## Current Architecture
- `pyqt_app.py`: Main UI and application logic
- `model_loader.py`: Model loading with ONNX/PyTorch support
- `video_processor.py`: Core detection and tracking pipeline
- `sort_tracker.py`: SORT tracking implementation
- `simple_tracker.py`: Lightweight IOU tracker
- `person_classifier.py`: Pedestrian/Rider classification
- `roi_manager.py`: ROI polygon management

## Known Constraints
- RTSP streams have latency issues (buffering, lag)
- DeepSORT is slow on CPU
- Memory accumulation in long sessions (trails, tracker history)
- Ghost tracks appear during network lag
- Frame pacing issues cause stuttering

## Enhancement Session (2026-03-26)
- Added new tracker option: `ByteTrack (Balanced)` integrated in PyQt UI and runtime tracker factory.
- Implemented lightweight ByteTrack-style module: `src/tracking/byte_tracker.py` using two-stage association:
  - Stage 1: match high-confidence detections to existing tracks.
  - Stage 2: recover unmatched tracks with low-confidence detections.
- Fixed display FPS view under-reporting in `pyqt_app.py`:
  - `render_fps_counter` now measures real UI render-loop cadence, not only frames that required redraw.

### Impact
- Better ID stability than plain SORT in crowded/noisy scenes while staying much lighter than DeepSORT.
- FPS card now aligns better with user-perceived smoothness; avoids false low `Display FPS` when frame content is static.

### Tradeoffs
- ByteTrack implementation is lightweight and does not include full motion-state estimation (velocity kept at 0), prioritizing reliability and low overhead.
- Display FPS reflects render loop cadence; if UI thread is throttled externally, displayed value follows UI reality.

## Enhancement Session (2026-03-28 - Source Switching and Legacy Key Dedupe)
- Fixed duplicate-source creation caused by legacy `source_key` values in saved settings:
  - `load_settings()` now canonicalizes `source_key` from `source` and deduplicates same-source profiles by canonical key.
  - When duplicates are merged, active source id is remapped safely.
- Hardened runtime duplicate checks:
  - `_find_source_profile_index()` and `_upsert_source_profile()` now always prefer canonical key computed from `source` and overwrite stale stored keys.
  - `_upsert_source_profile()` now refreshes `source` + `source_key` when updating existing entries.
- Fixed admin-grid row mapping bugs when active-source pinning changes visual order:
  - `rename_selected_admin_source()` now maps selected tile -> profile id -> true source row.
  - `_update_admin_card_preview_icon()` now resolves row by `admin_row_profile_ids` instead of assuming raw list index alignment.
- Reduced stale old-source frames during source switch:
  - Added `_reset_runtime_frame_state()` and use `stop_processing(clear_display=True)` before restart, so render state/store is reset immediately when changing source.
- Prevented stale async YouTube resolve callbacks from hijacking current source:
  - Added `_cancel_pending_stream_resolve()` and guarded resolve callbacks to ignore outdated pending requests after user switches source.

### Impact
- Switching sources on UI main no longer keeps old source visible for noticeable seconds in normal transitions.
- Legacy duplicated source entries from mixed `source_key` formats are merged at load time, reducing duplicate cards/profiles.
- Admin operations (rename/preview update) remain correct even with pinned-active sorting.

### Tradeoffs
- During source switching, player now clears frame immediately and may briefly show a transition message instead of freezing last frame.
- Dedup on load keeps one profile per canonical source; if users intentionally duplicated same URL with different names, only one survives.
